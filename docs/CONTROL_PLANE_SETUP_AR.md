# CraftMate — إعداد غرفة التحكم الواحدة

## الهدف

تقليل التوقفات إلى الصفر تقريباً دون تسليم مفاتيح حسابات رئيسية في المحادثة. يصبح GitHub هو غرفة التحكم: الكود يدخل مرة، وGitHub Actions تختبر وتبني وتنشر.

## 1. مفتاح نشر GitHub مخصص للمستودع

يتم إنشاء مفتاح SSH من نوع Deploy Key:

- يعمل على مستودع `SAYED1135/CraftMate-AI` فقط.
- يمكن إلغاؤه في أي وقت من إعدادات المستودع.
- لا يفتح حساب GitHub كاملاً ولا مستودعات أخرى.
- عند تفعيل **Allow write access** يمكن استخدامه لدفع الكود والوسوم فقط.

خطوات المالك لمرة واحدة:

1. افتح المستودع على GitHub.
2. اذهب إلى **Settings → Deploy keys → Add deploy key**.
3. العنوان: `CraftMate Agent Deploy Key`.
4. الصق المفتاح العام الذي يظهر في محادثة الإعداد.
5. فعّل **Allow write access**.
6. اضغط **Add key**.

بعدها يتم اختبار الاتصال ودفع فرع/وسم تجريبي قبل أي نشر إنتاجي.

## 2. أسرار GitHub Actions — تدخل مرة واحدة في GitHub فقط

من **Settings → Secrets and variables → Actions** أضف ما يلزم على مراحل:

| الاسم | القيمة | الاستخدام |
|---|---|---|
| `CLOUDFLARE_ACCOUNT_ID` | معرّف حساب Cloudflare | نشر Worker |
| `CLOUDFLARE_API_TOKEN` | Token محدود بصلاحية تعديل Workers للحساب | نشر Worker من Actions |
| `SUPABASE_PROJECT_REF` | `fucsztovkkilyboinhrv` | ربط هجرات قاعدة البيانات عند تفعيلها آلياً |
| `SUPABASE_ACCESS_TOKEN` | Token إدارة Supabase محدود/قابل للإلغاء | تشغيل الهجرات من بيئة التجربة/الإنتاج عند اعتماد البوابة |

لا يتم إدخال `SUPABASE_SERVICE_ROLE_KEY` في GitHub إلا إذا احتاجت خطوة آلية مستقبلية إلى إعادة ضبط Secret الـ Worker؛ الوضع المعتمد حالياً أن يبقى داخل Cloudflare Worker Secret فقط.

## 3. ماذا يحدث بعد الإعداد؟

- دفع كود الموقع/اللوحة: اختبارات أساسية ثم نشر GitHub Pages وفق إعداد المستودع.
- تعديل `worker/**`: نشر Worker والتحقق من `/health` عند توفر أسرار Cloudflare.
- دفع وسم مثل `v0.3.1`: بناء JAR ونشره في GitHub Release مع SHA-256.
- تغييرات قاعدة البيانات: لا تمر آلياً إلى الإنتاج قبل بيئة تجربة وبوابة اعتماد مكتوبة.

## 4. ما يبقى عند المالك فقط

- الموافقة على تسجيلات الدخول والمصادقة الثنائية.
- تدوير أي سر ظهر في محادثة.
- إدخال بيانات SMTP في Supabase/Resend.
- رفع JAR إلى شركة استضافة Minecraft وإعادة تشغيل سيرفر اللعبة.

بهذا الشكل لا تتحول كل مهمة إلى طلب جديد؛ إجراءات المالك تتجمع في الإعداد الأول وفي إصدارات الحسابات فقط.
