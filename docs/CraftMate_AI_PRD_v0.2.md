## سجل التغييرات في الإصدار 0.2 (Changelog v0.1 $\rightarrow$ v0.2)

1. **اعتماد المعمارية المجانية بالكامل ($0 GitHub-First Architecture):** توظيف GitHub Pages، وGitHub Actions، وGitHub Releases، وGitHub OAuth، بالتكامل مع الطبقات المجانية لـ Cloudflare Workers وSupabase لتشغيل المشروع بتكلفة صفرية.
2. **تعديل بروتوكول اتصال البلجن (HTTPS Polling بدل WebSocket المستمر):** استبدال الاتصال المستمر المكلّف بنظام نبضات (REST/HTTPS Heartbeat & Task Polling) يناسب الاستضافات المجانية والخوادم السحابية المجانية (Serverless).
3. **تحديد الاستضافات الأربع المدعومة رسمياً في الـ MVP:** حصر الدعم الرسمي الأولي في (`play.hosting`، `falixnodes.net`، `mcserverhost.com`، `minefort.com`) مع بناء ملف تعريفي (Host Profile) وقواعد سياسات خاصة بكل استضافة بالاستناد إلى مرجعية قائمة [Free-Minecraft-Hosts (FMHL)](https://github.com/Myuui/Free-Minecraft-Hosts).
4. **إضافة حالة "السبات" (Hibernation / Sleep Mode):** التمييز برمجياً بين توقف السيرفر الطبيعي لعدم وجود لاعبين في الاستضافات المجانية وبين التوقف الناتج عن عطل (Crash).
5. **إلزامية النشر على Modrinth وHangar:** لضمان قدرة مستخدمي الخطة المجانية في `FalixNodes` على تثبيت بلجن `CraftMate Connector` عبر متجر الإضافات المدمج لديهم.
6. **سد الفجوات الهندسية:** إضافة أنبوب تقليص السجلات (Log Deduplication)، التنقيح المزدوج للأسرار (Dual-Layer Scrubbing)، الربط مع Modrinth/Hangar API لفحص التوافق الفعلي، ودعم تقارير **Spark** وتحسينات الـ RAM المحدودة (1GB–4GB).

# 1. الملخص التنفيذي

**CraftMate AI** هو مساعد ذكي لإدارة وتشخيص سيرفرات Minecraft (يركز في النسخة الأولى على **Paper** و**Purpur**). هدفه أن يفهم نوع السيرفر وإصداره والبلجنز المثبتة، وخصائص الاستضافة والصلاحيات المتاحة، ثم يفسر طلب صاحب السيرفر ويقترح خطة عمل دقيقة ومبنية على الأدلة. يمكنه قراءة السجلات (`latest.log` و`crash reports`) وتحليل الأعطال والتوافق والأداء، وتقديم خطة مخصصة لدعم **Java وBedrock** بحسب قيود كل استضافة، ثم تنفيذ الإجراءات المسموح بها بعد موافقة المشرف والتحقق من نتيجتها.

المنتج ليس خدمة استضافة Minecraft، وليس مجرد بوت Discord. الواجهة الأساسية هي **لوحة ويب مستضافة مجاناً على GitHub Pages**، والذكاء الاصطناعي (**Gemini API**) يعمل كطبقة تحليل وتخطيط منضبطة، أما التحقق من السياسات وتنفيذ الإجراءات فيتم عبر **Backend خفيف ومجاني** وبلجن موثوق (**CraftMate Connector**).

# 2. المشكلة والفرصة

* **تعقيد التشخيص:** أصحاب السيرفرات (خصوصاً على الاستضافات المجانية والاقتصادية) يواجهون أخطاء وسجلات طويلة ومشكلات أداء (Out of Memory / Lag) وتوافق يصعب تشخيصها.
* **اختلاف القيود باختلاف الاستضافة:** الحل الذي ينجح على استضافة قد يكسر السيرفر على استضافة أخرى؛ فمثلاً `Minefort` يعمل خلف بروكسي BungeeCord مركزي إجباري، و`FalixNodes` يقيد رفع ملفات `.jar` الخارجية في الخطة المجانية، بينما `Play.hosting` و`MCServerHost` يتيحان صلاحيات ملفات ومنافذ أوسع.
* **إشكالية Java & Bedrock:** تثبيت بلجن Geyser وحده لا يضمن عمل Bedrock؛ إذ تختلف طريقة تخصيص منفذ UDP أو مشاركة المنفذ الأساسي أو إعداد Floodgate من استضافة لأخرى.
* **قصور الأدوات التقليدية:** لوحات التحكم تعرض السجلات أو تنفذ أوامر، لكنها لا تربط بين هدف المستخدم وقيود الاستضافة الفعلية.

**الفرصة:** تقديم مساعد ذكي مجاني يفهم السياق الفعلي وطبيعة الاستضافة المختارة، يشرح السبب بلغة واضحة، يضع خطة آمنة قابلة للمراجعة، وينفذ فقط ما تسمح به البيئة.

# 3. الرؤية ومبادئ المنتج

1. **الفهم قبل التنفيذ:** اجمع الحقائق وحدد المجهول وقيود الاستضافة قبل اقتراح أي تغييرات.
2. **الشفافية والأدلة:** اشرح لماذا اقترحت كل خطوة، واربط كل تشخيص بسطر من السجل أو إعداد فعلي، مع توضيح المخاطر.
3. **الموافقة البشرية (Human-in-the-Loop):** لا تنفذ أي تغييرات تمس الإعدادات أو حالة السيرفر دون موافقة صريحة من المشرف.
4. **أقل صلاحية (Least Privilege):** كل مكوّن يحصل على الصلاحيات الضرورية فقط، ولا يُسمح للنموذج بتوليد أوامر حرة (No Raw Shell/Command Execution).
5. **الوعي بالاستضافة (Host-Aware Intelligence):** التكيف التلقائي مع خصائص الاستضافات الأربع المدعومة، والتحول إلى "وضع الإرشاد اليدوي" عند وجود قيد يمنع التنفيذ الآلي.
6. **التشغيل الاقتصادي المستدام ($0 First):** بناء المنصة بالاعتماد على البنية التحتية المجانية لـ GitHub والخدمات السحابية المجانية دون التحايل على شروط الخدمة.

# 4. الأهداف ومؤشرات النجاح

## أهداف النسخة الأولى (MVP)
* اكتشاف ملف تعريفي موثوق للسيرفر والاستضافة من البيانات المتاحة.
* تحليل `latest.log` وملفات `crash reports` وتقارير `Spark` وتقديم تشخيص مدعوم بأدلة.
* دعم رسمي ومفصّل لأربع استضافات أساسية: **`play.hosting`**، **`falixnodes.net`**، **`mcserverhost.com`**، و**`minefort.com`**.
* تفسير حالة **Java/Bedrock** (Geyser/Floodgate/Proxy) وإظهار خطوات الإعداد المتوافقة مع كل استضافة من الاستضافات الأربع.
* إنشاء خطط إجراءات واضحة مع الموافقة والتسجيل والتحقق بعد التنفيذ.
* دعم **Paper / Purpur** أولاً (للإصدارات الحديثة 1.20.4 و1.21.x)، مع تصميم يسمح بإضافة Fabric وVelocity لاحقاً.

## مؤشرات القياس المقترحة (KPIs)
* نسبة التشخيصات التي تشير إلى سبب مدعوم بسطر سجل أو معلومة بيئية صريحة ($\ge 90\%$ في الحالات المختبرة).
* نسبة الخطط التي يوافق عليها المستخدم بعد مراجعتها دون تعديل يدوي معقد.
* نسبة الإجراءات الناجحة التي تم التحقق منها، ومعدل الفشل أو التراجع (Rollback).
* زمن الوصول إلى أول تشخيص مفيد (أقل من 15 ثانية عند رفع السجل).
* معدل الإنذارات الكاذبة (خصوصاً عدم الخلط بين وضع السبات الطبيعي `Hibernation` وبين أعطال السيرفر `Crash`).

# 6. نطاق المنتج

## 6.1 ضمن نطاق MVP (In-Scope)
* **لوحة ويب تفاعلية (مستضافة على GitHub Pages):** تدعم العربية (RTL) والإنجليزية، لعرض السيرفرات، حالة الاتصال/السبات، التشخيصات، الخطط، الموافقات، وسجل النشاط.
* **مسار رفع السجلات اليدوي (Doctor Mode):** تحليل فوري لملفات `latest.log` و`crash-reports` وملفات الإعدادات الأساسية حتى بدون تثبيت البلجن.
* **بلجن `CraftMate Connector` لـ Paper/Purpur:** يُبنى آلياً عبر GitHub Actions ويُنشر على **GitHub Releases** و**Modrinth** و**Hangar** لجمع البيانات وتنفيذ الإجراءات الآمنة ضمن قائمة سماح (Allowlist).
* **Backend مجاني (Cloudflare Workers + Supabase Free):** للمصادقة (GitHub OAuth / Email)، إدارة السيرفرات، تنقيح الأسرار، تنسيق المهام عبر HTTPS Polling، وسجل التدقيق.
* **تكامل مع Gemini API (Free Tier + BYOK اختياري):** لتحليل السجلات وإخراج خطط منظمة بصيغة JSON Schema صارمة.
* **قواعد مخصصة للاستضافات الأربع المدعومة:** (`play.hosting`، `falixnodes.net`، `mcserverhost.com`، `minefort.com`).

## 6.2 خارج نطاق MVP (Out-of-Scope)
* تقديم خدمة استضافة Minecraft أو إبقاء السيرفرات المجانية شغالة 24/7 بالتحايل على أنظمة السبات (Anti-AFK Bots ممنوعة تماماً).
* التحكم العام في نظام التشغيل أو تنفيذ أوامر Shell حرة يولدها النموذج.
* دعم كامل لكل الاستضافات العشوائية منذ اليوم الأول (الاستضافات خارج القائمة الأربع تعمل في وضع "رفع السجلات والتشخيص العام").
* الحظر الآلي للاعبين اعتماداً على حكم الذكاء الاصطناعي وحده.
* استبدال لوحة الاستضافة الأساسية (مثل Pterodactyl أو لوحة Minefort/Falix) بالكامل.

## 7.2 الاستفادة من قائمة `Myuui/Free-Minecraft-Hosts` للتوسع والتصنيف
يُخزن النظام ملف `hosts-profiles.json` في مستودع GitHub لتصنيف بقية الاستضافات في السوق إلى ثلاث فئات:
1. **مرشحات التوسع المستقبلي (Phase P7):** مثل `MineStrator` (4GB RAM + WebSFTP) و`FreeMCServer.net` و`AxentHost` و`HidenCloud`.

3. **استضافات سحابية خام (Oracle Cloud / Google Cloud):** تُوجه لاستخدام إرشادات الإعداد الكامل أو الـ Agent المستقبلي.

# 8. المتطلبات الوظيفية (Functional Requirements)

* **FR-01 — تسجيل الدخول والمشاريع:** يستطيع المستخدم تسجيل الدخول مجاناً (عبر **GitHub OAuth** أو البريد الإلكتروني عبر Supabase Auth)، وإنشاء مساحة عمل وإضافة سيرفر مع تحديد نوع الاستضافة من القائمة (`Play.hosting`، `FalixNodes`، `MCServerHost`، `Minefort`، `أخرى`).
* **FR-02 — ربط السيرفر الآمن:** يصدر النظام رمز ربط مؤقتاً أحادي الاستخدام (صالح لمدة 15 دقيقة)، ويُخزن سر الاتصال بصورة مشفرة (Hashed Token) ولا يظهر كاملاً بعد إنشائه.
* **FR-03 — اكتشاف البيئة والاستضافة:** يجمع البلجن معلومات النوع (Paper/Purpur) والإصدار وإصدار Java والبلجنز المثبتة وحجم الذاكرة المخصصة (`Max Memory` من الـ JVM) والقدرات المتاحة، ويدمجها مع ملف تعريف الاستضافة المختار.
* **FR-04 — نموذج القدرات (Capabilities Model):** يمثل النظام كل قدرة (`read_logs`، `read_config`، `edit_config`، `run_safe_command`، `custom_jar_upload`، `extra_udp_port`) بحالة موثقة: (`متاحة`، `غير متاحة بسبب الاستضافة`، `غير معروفة`، `تحتاج اختباراً`).
* **FR-05 — تحليل السجلات وتقليصها (Log Analysis & Deduplication):** يقوم النظام بتجميع الأخطاء المتكررة (Stacktrace Deduplication) قبل إرسالها إلى Gemini لتوفير التوكنز، ويستخرج الأخطاء والتحذيرات والسياق المحيط بها مع درجة ثقة ودليل نصي مباشر.
* **FR-06 — تشخيص الأداء والرام المحدودة (Performance & Low-RAM Tuning):** يقرأ مؤشرات TPS/MSPT المتاحة ويدعم تحليل روابط/ملفات **Spark Profiler** المدمج في Paper/Purpur، ويقدم توصيات مخصصة للسيرفرات ذات الرام المحدودة (خصوصاً 1GB في Minefort و2.5GB في FalixNodes).
* **FR-07 — تحليل التوافق الموثّق (Grounded Compatibility Check):** يفحص إصدارات البلجنز والتبعيات بالاستعانة بواجهات **Modrinth API** و**Hangar API** المجانية لتزويد Gemini بحقائق دقيقة ومنع الهلوسة في أرقام الإصدارات.
* **FR-08 — خطة الإجراءات المهيكلة:** ينشئ خطة تحتوي على الهدف، الخطوات، الملفات أو الأوامر المطلوبة، المخاطر، التحقق من عدم تعارضها مع قيد الاستضافة (مثل قيد `bungeecord` في Minefort)، وخطة التراجع (Rollback).
* **FR-09 — الموافقات البشرية:** لا تُنفذ الإجراءات التي تغيّر الحالة قبل موافقة مستخدم مخول؛ الموافقة مرتبطة بخطة محددة وبصمة حالة (State Hash) وتنتهي صلاحيتها بعد 30 دقيقة.
* **FR-10 — محرك تنفيذ مقيد (Policy Engine):** يتحقق الـ Backend من نوع الإجراء ومعاملاته وقواعد الاستضافة قبل وضع المهمة في طابور البلجن.
* **FR-11 — التحقق بعد التنفيذ والنسخ الاحتياطي:** يحتفظ البلجن بنسخة احتياطية محلية للملف قبل تعديله (`.bak`)، ويتحقق من سلامة صيغة YAML قبل الحفظ، ثم يفحص السجل بعد التنفيذ للتأكد من عدم ظهور أخطاء جديدة.
* **FR-12 — سجل تدقيق (Audit Log):** يسجل المستخدم والإجراء والوقت والهدف والنتيجة والموافقة، مع إخفاء الأسرار.
* **FR-13 — تشخيص Java/Bedrock المخصص للاستضافة:** يكتشف وجود Geyser/Floodgate وإعداداتهما، ويقدم خطة إعداد مطابقة للاستضافة المختارة (مثلاً: استخدام تبويب `Network -> Ports` في FalixNodes، أو احترام بروكسي Minefort).
* **FR-14 — رفع الملفات يدوياً:** يسمح برفع `latest.log` وتقارير الأعطال وملفات إعدادات محددة (`server.properties`, `spigot.yml`, `paper-global.yml`, `config.yml` لـ Geyser) بحد أقصى `15 MB` للملف النصي.
* **FR-15 — تجربة المستخدم الثنائية:** يدعم الواجهة العربية (RTL) والإنجليزية، مع ضمان عرض السجلات والأكواد باتجاه `LTR` سليم، ويشرح المصطلحات للمبتدئين.
* **FR-16 — إدارة الاتصال ووضع السبات (Hibernation Handling):** يميز النظام بين ثلاث حالات لانقطاع البلجن:
  1. **`ONLINE`:** البلجن يرسل نبضات (Heartbeat) منتظمة.
  2. **`HIBERNATING (في وضع السبات)`:** السيرفر أُغلق بشكل طبيعي (`onDisable` نظيف أو 0 لاعبين في استضافة مجانية مثل Minefort/Falix)؛ لا يُعرض كخطأ بل كحالة طبيعية.
  3. **`OFFLINE / CRASHED`:** انقطاع مفاجئ أثناء وجود نشاط أو بعد ظهور Crash في السجل.

# 9. المتطلبات غير الوظيفية والمعايير الهندسية

* **التكلفة الصفرية ($0 Infrastructure):** يجب أن تعمل النسخة الأولية بالكامل ضمن الحصص المجانية لـ GitHub وCloudflare Workers وSupabase وGemini API دون الحاجة لخوادم مدفوعة.
* **الأمان:** اتصال TLS إلزامي، تشفير الرموز، وعدم تخزين أي مفاتيح سرية لـ Gemini أو قاعدة البيانات داخل كود الواجهة الأمامية أو داخل ملف `.jar` الخاص بالبلجن.
* **الاعتمادية (Fail-Safe Plugin):** انقطاع الـ Backend أو انتهاء حصة Gemini لا يوقف سيرفر Minecraft ولا يسبب أي تجميد (Freeze)؛ جميع طلبات الشبكة في البلجن تعمل على خيط غير متزامن (`Async Thread`).
* **الخصوصية وتنقيح البيانات (Dual-Layer Scrubbing):** حذف عناوين IP الخاصة باللاعبين، كلمات مرور RCON، روابط قواعد البيانات (MySQL URIs)، والتوكنات في **طبقتين**: داخل البلجن قبل الإرسال، وداخل الـ Backend قبل استدعاء Gemini.
* **المعايير الرقمية للتصميم (Design Constraints):**
  * فترة نبضة البلجن (`Heartbeat Interval`): كل **45–60 ثانية** (لتقليل استهلاك حصة طلبات الـ Serverless).
  * الحد الأقصى لحجم مقطع السجل المرسل في المهمة الواحدة: **500 سطر منقّح** (أو `100 KB` بعد ضغط الأخطاء المتكررة).
  * مدة صلاحية رمز الربط المؤقت (`Pairing Code TTL`): **15 دقيقة**.
  * مدة صلاحية الخطة المعتمدة قبل التنفيذ (`Approval TTL`): **30 دقيقة**.

## 10.2 بلجن الاتصال `CraftMate Connector` وبروتوكول HTTPS Polling

### لماذا HTTPS Polling بدلاً من WebSocket في النسخة المجانية؟
الخوادم السحابية المجانية (مثل Cloudflare Workers) مصممة للطلبات السريعة القصيرة وليس للاتصالات المفتوحة على مدار الساعة، كما أن سيرفرات الاستضافات المجانية تدخل في وضع السبات باستمرار. لذلك يعتمد البلجن على **Outbound HTTPS Heartbeat & Task Polling**:
1. يتصل البلجن كل **60 ثانية** (أو فوراً عند كتابة المشرف أمر `/craftmate sync` داخل السيرفر) بنقطة النهاية `POST /v1/connector/heartbeat`.
2. يرسل البلجن حالة السيرفر المختصرة (TPS، الذاكرة المستخدمة، عدد اللاعبين) ويستقبل في نفس الرد قائمة المهام المعتمدة التي تنتظر التنفيذ (`pending_tasks`).
3. ينفذ البلجن المهمة المسموح بها ويرسل النتيجة إلى `POST /v1/connector/task-result`.
4. عند إغلاق السيرفر طبيعياً (`onDisable()` في Bukkit/Paper API)، يرسل البلجن إشارة أخيرة `POST /v1/connector/shutdown` مع سبب الإغلاق، ليقوم الـ Backend بتحويل حالة السيرفر إلى **`HIBERNATING`** بدلاً من **`CRASHED`**.

### استراتيجية توزيع البلجن (لحل قيد FalixNodes المجاني)
* يتم إعداد سير عمل **GitHub Actions** في مستودع البلجن يقوم عند كل إصدار (`git tag v*`) بـ:
  1. بناء ملف `CraftMate-Connector.jar` عبر Gradle.
  2. رفعه تلقائياً إلى **GitHub Releases** (لأصحاب `Play.hosting` و`MCServerHost` و`Minefort`).
  3. نشره تلقائياً عبر واجهات البرمجة الرسمية إلى **Modrinth** و**Hangar (PaperMC)**، مما يتيح لمستخدمي **FalixNodes (الخطة المجانية)** تثبيته مباشرة من داخل لوحة تحكم Falix دون الحاجة لرفع ملف `.jar` خارجي.

# 11. دورة الطلب من البداية للنهاية (End-to-End Request Lifecycle)

1. **تحديد الهدف:** يكتب المستخدم مشكلته أو هدفه في لوحة التحكم (أو يرفع ملف `latest.log` يدوياً).
2. **تجميع السياق وملف الاستضافة:** يجلب الـ Backend ملف تعريف السيرفر (`Paper 1.21.1`) وملف الاستضافة المختارة (مثلاً: `Minefort` $\leftarrow$ الرام 1GB، بروكسي BungeeCord مفعل إجبارياً).
3. **تنقيح وتقليص البيانات:** تُحذف الأسرار وعناوين الـ IP، وتُدمج الأخطاء المتكررة في السجل، وتُفحص إصدارات البلجنز عبر Modrinth/Hangar API.
4. **التحليل عبر Gemini:** يُرسل السياق المنقّح مع قيود الاستضافة إلى Gemini API، ويُطلب منه إخراج كائن JSON يتبع مخططاً صارماً (التشخيص، الأدلة مع أرقام الأسطر، درجة الثقة، خطوات الإصلاح).
5. **فحص محرك السياسات (Policy Engine):** يتحقق المحرك من كل خطوة مقترحة:
   * هل الإجراء ضمن قائمة السماح (Allowlist)؟
   * هل يتعارض مع قيد الاستضافة؟ (مثال: لو اقترح تعديل `bungeecord: false` في `Minefort`، يرفضه المحرك تلقائياً!).
6. **العرض والموافقة:** تعرض لوحة التحكم السبب والأدلة والمخاطر وخطة التراجع، ويضغط المشرف على **"موافقة وتنفيذ"** (أو يختار تطبيق الخطوات يدوياً إذا كانت القدرة غير متاحة آلياً).
7. **التنفيذ والتحقق:** يستلم البلجن المهمة في النبضة التالية، يأخذ نسخة احتياطية للملف، ينفذ الإجراء، ثم يتحقق من السجل ويرسل التقرير النهائي للوحة التحكم.

# 12. إدارة ملف Java وBedrock حسب الاستضافة

في الـ MVP، يقدم النظام **خطة إعداد وتشخيص مخصصة لكل استضافة** من الاستضافات الأربع:

1. **على `Play.hosting`:**
   * يتحقق النظام من وجود Geyser/Floodgate، ويوجه المستخدم إما لتفعيل ميزة Crossplay المدمجة أو تخصيص منفذ إضافي (19132 UDP) وربطه في `config.yml` الخاص بـ Geyser مع `clone-remote-port: false` (أو `true` إذا شارك المنفذ).
2. **على `FalixNodes`:**
   * يفحص النظام إعدادات `Geyser-Spigot/config.yml`، ويشرح للمستخدم خطوات إنشاء منفذ من تبويب `Network -> Ports` في لوحة Falix ووضعه في حقل `bedrock.port`، أو تفعيل `clone-remote-port: true` لاستخدام المنفذ الأساسي.
3. **على `MCServerHost`:**
   * يتحقق من رفع كلٍ من `Geyser-Spigot.jar` و`Floodgate-Spigot.jar` في مجلد `plugins`، ويتأكد من ضبط `auth-type: floodgate` ووجود ملف `key.pem` الصحيح.
4. **على `Minefort`:**
   * ينبّه المستخدم إلى أن `Minefort` يدير الاتصالات عبر البروكسي المركزي (`play.minefort.com`)، ويمنع العبث بإعدادات `bungeecord`، ويشخص مشكلات توافق إصدارات الكلاينت عبر اقتراح `ViaVersion` / `ViaBackwards` عند تأخر تحديث البروكسي.

# 13. الأمان والتهديدات (Threat Model)

| التهديد الأمني | آلية المعالجة الهندسية في v0.2 |
| :--- | :--- |
| **كشف مفتاح Gemini API في GitHub Pages** | يُمنع وضع المفتاح في الواجهة الأمامية؛ يُحفظ حصراً كـ Encrypted Secret في Cloudflare Workers (أو يدخل المستخدم مفتاحه الشخصي محلياً في متصفحه في وضع BYOK). |
| **سرقة رمز ربط السيرفر** | رمز مؤقت أحادي الاستخدام (15 دقيقة)، يُستبدل بتوكن طويل الأمد مشفر بـ SHA-256 قابل للإلغاء فوراً من لوحة التحكم. |
| **تنفيذ أمر خطر بسبب هلوسة النموذج** | لا توجد أوامر Shell أو أوامر حرة؛ البلجن لا ينفذ إلا وظائف محددة برمجياً (Hardcoded Action Handlers) بمعاملات مفحوصة. |
| **Prompt Injection داخل السجلات أو أسماء اللاعبين** | فصل السجلات في وسم بيانات مستقل غير قابل للتنفيذ، وتطبيق فلاتر Regex قبل الإرسال، وعدم منح النموذج صلاحية تنفيذ مباشر. |
| **كسر السيرفر بسبب اقتراح غير متوافق مع الاستضافة** | تطبيق قواعد `hosts-profiles.json` في محرك السياسات (مثل حماية إعدادات `spigot.yml` في Minefort) وأخذ نسخة `.bak` قبل أي تعديل. |
| **استنزاف الحصة المجانية (Quota Exhaustion)** | تقليص السجلات قبل الإرسال، استخدام نموذج `Gemini 2.5 Flash` السريع والاقتصادي للتشخيصات اليومية، ووضع حد أقصى لعدد التحليلات اليومية لكل مستخدم. |

# 14. الخصوصية وحماية البيانات

* **تقليل البيانات (Data Minimization):** لا يتم رفع محادثات اللاعبين العادية (`[Async Chat Thread]`) أو إحداثيات قواعدهم في السجلات ما لم تكن جزءاً مباشراً من Stacktrace لعطل برمجي.
* **التنقيح التلقائي:** استبدال عناوين الـ IP بـ `[REDACTED_IP]` وكلمات المرور والتوكنات بـ `[REDACTED_SECRET]` داخل البلجن قبل خروجها من السيرفر.
* **الاحتفاظ بالبيانات (Retention Policy):** لتناسب المساحة المجانية في Supabase (500MB)، يتم الاحتفاظ بالسجلات الخام لمدة **7 أيام كحد أقصى** (أو حذف النص الخام فور استخراج التقرير المهيكل)، مع إتاحة زر حذف فوري لجميع بيانات السيرفر.

# 17. معايير قبول النسخة الأولية (MVP Acceptance Criteria)

1. يعمل الموقع بالكامل عبر **GitHub Pages** بواجهة عربية (RTL) وإنجليزية نظيفة وسريعة.
2. يستطيع المستخدم اختيار إحدى الاستضافات الأربع (`play.hosting`، `falixnodes.net`، `mcserverhost.com`، `minefort.com`) والحصول على إرشادات مطابقة لبيئته.
3. يستطيع مستخدم الخطة المجانية في `FalixNodes` العثور على بلجن `CraftMate Connector` وتثبيته عبر Modrinth/Hangar.
4. يمنع محرك السياسات أي خطة تقترح تعطيل `bungeecord: true` لسيرفر مستضاف على `Minefort`.
5. عندما يدخل سيرفر مجاني في وضع السبات لعدم وجود لاعبين، تعرض اللوحة حالة **"في وضع السبات (Hibernating)"** ولا تصدر إنذار عطل كاذب.
6. لا توجد أي مفاتيح سرية خاصة بالمنصة مكشوفة في كود الواجهة الأمامية أو داخل ملف البلجن.
7. يستطيع المستخدم الاستفادة الكاملة من ميزة تشخيص السجلات يدوياً حتى دون تثبيت البلجن.
