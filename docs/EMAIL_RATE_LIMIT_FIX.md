# حل مشكلة `email rate limit exceeded` في Supabase Auth

## السبب الحقيقي

رسالة **`email rate limit exceeded`** (كود الخطأ `over_email_send_rate_limit`) لا تعني أن كلمة السر أو التطبيق مكسوران.
معناها أن Supabase رفض إرسال بريد تأكيد/دخول جديد لأن مشروعك يعمل على **مزوّد البريد المدمج التجريبي**:

| المزود | الحد |
|---|---|
| Supabase المدمج (افتراضي) | **رسالتان فقط في الساعة للمشروع كله** — ومقصود به الاختبار فقط، ولا يوصل فعلياً إلا لعناوين فريق المنظمة |
| مزوّد SMTP خاص (Custom SMTP) | يبدأ من **30 رسالة/ساعة** ويمكن رفعه من لوحة التحكم |

إعادة الضغط على التسجيل أو إعادة الإرسال لا تحل المشكلة، بل تستهلك المحاولات وتطيل الانتظار. يوجد أيضاً مهلة افتراضية 60 ثانية بين طلبات نفس المستخدم.

---

## الحل السريع للبيتا (دقيقة واحدة — لا بريد بعد اليوم)

لو الهدف تشغيل البيتا فوراً بلا احتكاك تسجيل:

1. افتح إعدادات المزوّد:
   https://supabase.com/dashboard/project/fucsztovkkilyboinhrv/auth/providers
2. اختر **Email**.
3. أوقف **Confirm email**.
4. احفظ.

النتيجة: التسجيل السحابي يعيد جلسة فورية (`access_token`) ويدخل المستخدم لوحته مباشرة من غير إرسال أي رسالة — فلا يظهر الخطأ أصلاً. التطبيق عندنا يدعم هذا السلوك تلقائياً.

المقايضة بوعي: عناوين البريد لن تكون مؤكدة في فترة البيتا. لذلك هذا وضع إطلاق مبكر، والحل التالي هو الإنتاجي.

> **مستخدمون سجّلوا ولم يؤكدوا قبل إيقاف التأكيد:** من **Authentication → Users** يمكن إدارة المستخدم العالق، أو يطلب رسالة تأكيد جديدة بعد إصلاح الإرسال. لا تحذف مستخدماً حقيقياً لمجرد أنه غير مؤكد.

## الحل الإنتاجي الدائم — Custom SMTP عبر Resend (مجاني)

### 1. أنشئ حساب Resend
- سجّل في https://resend.com واحصل على **API Key** من لوحته.
- للإنتاج الحقيقي: تحقق من دومين الإرسال الخاص بك داخل Resend (سجلات DNS يرشدك خلالها).

### 2. فعّله في Supabase
افتح:
https://supabase.com/dashboard/project/fucsztovkkilyboinhrv/auth/templates

ثم **SMTP Settings → Enable Custom SMTP** واملأ:

| الحقل | القيمة |
|---|---|
| Host | `smtp.resend.com` |
| Port | `465` |
| Username | `resend` |
| Password | مفتاح Resend API Key الخاص بك (لا يشارك في المحادثات ولا في GitHub) |
| Sender email | بريد على دومينك المؤكد، مثل `noreply@your-domain.com` |
| Sender name | `CraftMate AI` |

### 3. ارفع حد الساعة
افتح:
https://supabase.com/dashboard/project/fucsztovkkilyboinhrv/auth/rate-limits

ارفع **Emails sent per hour** من 30 إلى قيمة تناسب إطلاقك (ابدأ بـ 100). من دون هذه الخطوة ستصطدم بحد 30/ساعة بدل 2/ساعة.

### 4. اختبر
سجّل حساباً جديداً ببريد خارجي حقيقي (ليس من فريق Supabase) وتأكد وصول الرسالة، ثم راجع **Logs → Auth Logs** عند أي مشكلة.

## ماذا فعل التطبيق نفسه؟

في `app.html` تم تنفيذ حماية من تفاقم المشكلة:

- اكتشاف خطأ الحد (`429` / `over_email_send_rate_limit`) وعرض شرح عربي وإنجليزي بحلّين: الانتظار أو متابعة فورية بلا بريد.
- **مهلة قسرية 60 ثانية** تعطّل أزرار التسجيل والدخول وإعادة الإرسال بعد أي إرسال، بدل أن يحرق المستخدم الحد بمحاولات متكررة.
- زر **«إعادة إرسال رسالة تأكيد البريد»** رسمي عبر `POST /auth/v1/resend` — بدل إعادة إنشاء الحساب مراراً.
- رسالة خاصة واضحة عند خطأ «البريد غير مؤكد» ترشد المستخدم لرسالة التأكيد أو زر الإعادة مرة واحدة.

## ترتيب التنفيذ الموصى به الآن

1. **دلوقتي**: أوقف `Confirm email` (الحل السريع) ودع البيتا يعمل.
2. **قبل الإطلاق العام**: فعّل Resend Custom SMTP + ارفع حد Auth Rate Limits + أعد تشغيل `Confirm email`.
