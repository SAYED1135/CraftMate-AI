# Phase 0 — فحص عملي: play.hosting (2026-10-17)

## الهدف
التحقق عمليًا من إمكانية ربط CraftMate عبر Subusers على play.hosting قبل أي بناء.

## النتائج المؤكدة
1. اللوحة: https://panel.play.hosting — والتسجيل: /auth/register (رابط رسمي من موقعهم).
2. Subusers معلنة رسميًا ضمن مزايا كل سيرفر: "Invite subusers".
3. اللوحة محمية بـ Cloudflare Bot Challenge: أي طلب آلي من بيئة سحابية (حتى ببصمة متصفح) يرجع صفحة "Just a moment..." (403 + cf-mitigated: challenge) — ويشمل مسارات ‎/api/client‎.
4. لا يوجد نطاق API مستقل مكشوف (api.play.hosting غير متاح).
5. نفس الحماية ظاهرة عند فحص لوحات FalixNodes من بيئة سحابية (403).

## الاستنتاج الهندسي
- إنشاء الحساب وتسجيل الدخول الآلي من خوادم سحابية إلى هذه اللوحات غير موثوق تقنيًا بسبب حماية مكافحة البوتات المصممة أصلًا لمنع ذلك.
- الحل المتسق مع فكرة المالك: المنصة تجهز كل بيانات الحساب (إيميل/باسورد/اسم) وتفتح رابط التسجيل؛ المستخدم يكمل خطوة التحقق البشري (Cloudflare/كابتشا) في متصفحه بالبيانات الجاهزة؛ ثم يضيف Subuser بالإيميل والصلاحيات كالمخطط.
- يبقى التحقق من «ظهور السيرفر» والتنفيذ عبر Client API رهين اختبار حقيقي بمفتاح API من حساب فعلي (الاختبار التالي).

## الاختبار الحاسم التالي (يحتاج حسابًا حقيقيًا، ~5 دقائق من المالك)
1. إنشاء حساب تجريبي على play.hosting + سيرفر مجاني.
2. إنشاء حساب ثانٍ (حساب المنصة التجريبي) بالبيانات التي نجهزها.
3. إضافة الحساب الثاني Subuser بصلاحيات: عرض الكونسول + إرسال أوامر + بدء/إعادة تشغيل.
4. من حساب المنصة: إنشاء Client API Key.
5. نجرب من بيئتنا: استدعاء ‎GET /api/client‎ (هل يظهر السيرفر المشترك؟) ثم إرسال أمر كونسول غير مؤذٍ وملاحظة النتيجة.
- نجاح 5 = المسار الكامل قابل للبناء على play.hosting.
- فشل 5 بسبب Cloudflare = التنفيذ السحابي عبر هذه اللوحة محظور، ونوثق وننتقل لخطة بديلة لهذه الاستضافة.

## حالة الخطة
- FalixNodes: Subusers موثقة رسميًا بالكامل في قاعدة معارفهم (بديل جاهز للفحص بنفس الطريقة).
