# CraftMate — P2 Control Foundation Build `2026.10.17-ux4`

**التاريخ:** 2026-10-17

## الهدف
تحويل CraftMate من شات قراءة فقط إلى طبقة تحكم حقيقية عبر البلجن، مع الحفاظ على أن البلجن هو المسار النشط الوحيد داخل السيرفر الجاري.

## قرارات المالك المثبتة
- تفعيل التحكم الكامل من الموقع بعد الربط.
- أثناء جلسة التحكم، التنفيذ فوري (`full_instant`) ولا توجد بطاقة موافقة لكل عملية.
- أوامر الكونسول لاحقًا من قوالب جاهزة مُتحقق منها فقط، وليست أوامر حرة.

## اللي اتبنى في الشريحة دي
1. Migration جديدة `006_server_tasks_control.sql` لحالة التحكم وجدول `server_tasks` مع RLS للقراءة من المالك.
2. Worker `0.6.0` بمسارات:
   - `POST /v1/control/status`
   - `POST /v1/control/set`
   - `POST /v1/tasks/create`
   - `POST /v1/tasks/list`
   - `POST /v1/plugin/tasks/poll`
   - `POST /v1/plugin/tasks/result`
3. Connector source `0.5.0` مع polling دوري للمهام وإرسال النتائج، وتنفيذ المهام المقبولة محليًا من `AllowlistTaskExecutor`.
4. زر داخل شات السيرفر لتفعيل/إيقاف جلسة تحكم كاملة لمدة 60 دقيقة.
5. GitHub Actions build للتأكد أن البلجن بيتبني بـ JDK 21.

## أول مهام مسموحة
- `GET_ENVIRONMENT_SNAPSHOT`
- `GET_RECENT_LOGS`

دي مهام قراءة متعمدة قبل فتح أي كتابة. خطوة التوسع الجاية هي مهام config/files/plugin المُتحقق منها مع backup + verify + rollback، ثم قوالب كونسول جاهزة فقط.

## حدود صريحة ولسه سارية
- التحكم يعمل فقط والسيرفر الجاري والبلجن شغال.
- لا يشغّل سيرفر مطفي ولا يتحكم في لوحة الاستضافة.
- لا توجد أوامر كونسول حرة ولا shell نظام.
- لا كلمات سر استضافة ولا مفاتيح Gemini داخل الموقع أو البلجن.

## خطوة إعداد واحدة مطلوبة من المالك
تشغيل `supabase/migrations/006_server_tasks_control.sql` في Supabase SQL Editor مرة واحدة. بدونه الموقع يعرض رسالة ودية برمز الدعم `CM-CTRL-503` بدل ما يدّعي إن التحكم جاهز.

## الاختبارات
- Worker JS: `node --check` ناجح.
- Mock tests ناجحة لـ:
  - رفض حالة التحكم بدون تسجيل دخول `CM-CTRL-401`.
  - Poll آمن قبل تشغيل migration (`tasks_ready:false`).
  - منع إنشاء المهام والتحكم مقفول `CM-CTRL-403`.
  - إنشاء مهمة logs بقيم محدودة ووضعها `QUEUED`.
  - رفض الأنواع غير المعروفة `CM-TASK-422`.
- Plugin: يُتحقق من بنائه عبر GitHub Actions `plugin-build.yml`.

## Acceptance المتبقي
1. تشغيل migration 006.
2. بناء/نشر Connector 0.5.0 كـ JAR رسمي وتثبيته على سيرفر حقيقي.
3. تفعيل التحكم من الموقع وإنشاء مهمة logs/environment حقيقية ورؤية نتيجتها.
4. بعد نجاح مهام القراءة، فتح مهام الكتابة المُتحقق منها تدريجيًا.
